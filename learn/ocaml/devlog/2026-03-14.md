# Devlog No. 1

## Why am I Interested in OCaml?

Over a decade ago now, a professor challenged me to learn Haskell.
Over the next three months, I did, and then four months later I discovered I love it.
However, the time has come for me to build some low-level software, like runtime systems.
This _technically_ can be done in Haskell, but it's not easy, and even harder if you want to eliminate Haskell as a dependency.
In particular, I wanted to be able to statically link pre-compiled object fiels (say, from C) into Haskell libraries.
Cabal, Haskell's build system, just doesn't really support that.

So, I searched up OCaml to see if it had a better user story, and oh boy, does it!
At least, alledgedly,,, according to the documentation.

On the topic of documentation, OCaml has some excellent documentation.
Quick searches direct me to easy-to-read information targeting my exact area of concern.
I've yet to read any API docs yet, but I assume they'll be at least decent;
  from my Haskell experience, I know the OCaml type system is straightforward enough that even an undocumented library might be of help.

## What am I looking forward to?

OCaml's object system seems interesting, oriented as it is around row-polymorphism.
Could be good for prototyping, though "many seasoned OCaml programmers rarely use classes and objects".
I guess I'm just curious about open recursion with late binding; sounds useful for extensible ASTs or AST decor, perhaps.
I see there's something called "polymorphic variants" as well;
  I like a language that includes duals of features, and _that_ sounds useful for extensible ASTs.

## How am I setting up OCaml?

I'll say it _was_ a little tricky getting my nix flake set up for development.
Dune isn't advertized as being for OCaml, but it's there as `dune_3`.
Based on the NixOS wiki, I may need `ocamlPackages.findlib`.
I'm not sure if I need `opam` or if `dune` is enough.
There are several packages outside of dune+ocaml that are useful for development.
`utop` for an alledgedly better repl, `ocaml-lsp` for lsp support.
There's something for formatting, which I'll get to later.

I would love to get a nix development shell that manages my ocaml library dependencies.
Unfortunately, after several attempts, I'm just not sure how.
I did set up to have `dune` though, and I suppose I can just manage my ocaml through that like how I'm managing my haskell dependencies through `cabal`.
It's not the most stable dependency management, but I think it should work while I learn the language at least.

```
dune init project kissforth
# dune pkg lock # I ended up not using this
dune build
dune exec probe
```

It seems dune is building its dependencies from source, including the compiler, so it takes a long time at first.
That's precisely the sort of thing that nix would cache.

The difficulty seems to ramp up when I want to use `Base`.
It says `print_endline` from the standard library is deprecated, but treats that as an error.
Using `Stdio.print_endline` as suggested says that `Stdio` is unbound.
There's a trick on the dune faq for preventing what I'd call `-Werror`.

I did find one thing out: I have to `#require` in `utop`.
So, `utop` then `#require "base";; open Base;;` worked just fine from my nix env.
Then I did the same `#require` trick for Stdio.

Interestingly, `dune utop` doesn't work because the utop library isn't found.
I suspect I need a `dev-depends` stanza in my `dune-project`.

## Some Oddities

When I wanted to access soem library code, I needed to kinda demangle, which I wasn't expecting.
I have `lib/vm.ml`, which holds a `module Name = struct let v = ... end`.
To use it from `bin/main.ml`, I needed to say `Kissforth__Vm.Name.v`.
Why prefix with the package name and double underscores?
Who know, I haven't seen mention of it in the docs yet.
